GitHub Repository Links

Please find the link to create your repository for this assignment in the "GitHub Repo Creation Links" section under course resources. You may find course resources on the left side pane of your module view.

Implementation:

  1. You may implement the final project on your own, or organize in groups of up to 3 for this assignment.  All grading will be done individually based on your individual contribution to the project.  The total scope of the project should be the equivalent of at least 3 assignments (30-45 hours of implementation time per person) split as evenly between 3 sprints as possible.

  2. The link above will create an empty GitHub repository to store the individual portion of your assignment.

    1. For the Final Project Proposal submission you do not need to check any code into this repository.  However, you will add wiki pages and issues for each topic below.  

    2. Your final project repository will be publicly accessible (required for peer reviews).  

  3. The README.md in each student submission repository should link to a single “Project Overview” page in a single group member’s submission repository.  This is where the shared content related to the project will be created.

  4. The shared Project Overview wiki page should contain the following content, using this page (external link; opens in a new tab) as a template:

    1. An overview of the project goals and motivation.  Includes at least one diagram relevant to the overall project design which, at minimum, identifies the associated hardware.

    2. The target build system for the project, Buildroot or Yocto.

    3. The hardware platform selected.

      1. If using a hardware platform other than a platform listed as supported, links which detail how this platform can be supported by the build system of choice.

    4. Any open source projects (other than the current base platform Yocto/Buildroot packages used with assignments) intended to be used with the project.  If you intend to use no open source projects/packages please state this. Also add a link for each reference.

    5. Any previous assignment content intended to be used with the project.  If you do not intend to use previous assignment content, please state this.

    6. Previously discussed course content intended to be covered by the project implementation, and how this will be used in the project.  If you do not intend to use previous assignment content, please state this.

    7. Content not yet discussed or not covered in the course which is intended to be included in the project implementation and how this will be used in the project.

    8. If using the project with another course, the specific portions of the project which will be specific to this course (and implemented completely by you or your group).

    9. How you intend to organize the source code related to your project, especially for group projects:

      1. Which repository will hold the Buildroot or Yocto implementation (the suggestion is to use the project containing the Project Overview wiki page for this).

      2. Which repository/repositories will hold implementation scripts/source code for various project components

      3. Any additional repositories needed to store project content.

      4. Include the links to all repositories in your wiki with your submission.

    10. The team project members and the high level role of each project member in the overall project (group submissions only)

    11. A link to the shared schedule page (see detail below)

  5. A Schedule page linked from the Project Overview page and containing this content:

    1. Add your team members as collaborators to your final project GitHub repository created through the coursera instructions. Find instructions on GitHub (external link; opens in a new tab).

    2. One of the team members on your final project team should use the instructions in this Wiki page (external link; opens in a new tab) to create an Public empty repository in their personal GitHub account used to host a GitHub "Projects" page for your project. The Wiki page linked here should

      1. Please refer to this Reference Project (external link; opens in a new tab) for an example of the final layout of your Projects" page.

      2. All students in the team should be added to this repository as well to allow them to collaborate on the Projects page design. Find instructions for this step on GitHub (external link; opens in a new tab).

      3. Please link the Project created in this step to the Project Overview page for your final project

      4. Add links to issues in either the main project repository or individual student repositories tracking deliverables related to Sprint 1 items.

    3. At least one issue assigned to each student related to Sprint 1.

    4. All issues assigned include a complete Definition of Done (DoD), with sufficient detail to be understood by someone who is not a member of the project team.

    5. Any blockers between assigned issues are identified and linked.

    6. Tasks which have started include details about status.

    7. The top level schedule table is up to date with the content and status of individual issues.

Submission:

  1. Your submission in peer review must Include a Link to your (individual student) Final Project Repository which links to the overall project overview.

  2. Each student’s submission repository should contain a README.md pointing to the project overview page.

  3. The Project Overview page should contain all points referenced above (see the Assignment Peer Review rubric).

  4. Issues for at least Sprint 1 should be created as described in the schedule page, and include the content referenced above.

  5. The Schedule Page should be up to date and accurate.
