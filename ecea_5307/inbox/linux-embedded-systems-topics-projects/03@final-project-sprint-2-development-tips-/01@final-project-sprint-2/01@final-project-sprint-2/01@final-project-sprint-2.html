Implementation:

1. Check in all code for the project to your project repositories.  Your code should build and run, and status of the build should match the status given in issues on your project repositories.

2. Update your Project Overview wiki page with any changes since the last sprint or since the original project proposal.   See Project Overview for the template (same one used for the project proposal assignment).  If/when editing, add an edit message describing the reason for the change.

3. Update your Schedule page (based on Project Template), linked from your Project Overview wiki page, to schedule issues for the next upcoming Sprint and close any issues completed in the previous sprint.  For multi-person groups, each group member is responsible for ensuring sprint issues are assigned to them and ensuring they’ve closed issues assigned to them resolved in the current sprint with appropriate detail included.  When necessary (if project overview sections have become out of date), students must update the project overview wiki page based on issues assigned to them.

  • Closed issues should be assigned to the group member who closed them, and updated by this group member.  At least one closed issue should be assigned to each member to track what they accomplished in the current sprint.

  • A comment in closed issues should mention that Definition of Done is verified, with any relevant details including a general description or link to code changes made and description of testing which was performed.  The Definition of Done should be updated, if necessary, to match what was completed in the sprint.

  • If a sprint item is partially done, you should redefine the issue to include the portions already done, mark the item resolved in the sprint, move undone portions to a new item, and reference this item in the resolved issue as the follow-on task.

  • Issues should be assigned for each group member in the upcoming sprint with DoD defined.

  • Blockers should be identified and updated for closed and updated/new issues.

  • Use the “edit” option to edit the description and ensure it is up to date for each issue before closing.
