## 5. Linux Device Update

**Q1. Obfuscation can remove the need for cryptography in OTA security.** ✅ **False**. Obfuscation ≠ cryptography.

**Q2. Important design goals for an update scheme (select all)**
✅ **Prevent unauthorized code replacement** ✅ **Ability to recover from power loss or connection outages** ✅ **Ease of use for end users as well as developers**
(❌ "Use obfuscation to transfer encryption keys".)

**Q3. Which scheme uses the most storage?** ✅ **A/B Dual Redundant** (2× rootfs).

**Q4. Label the signature *generation* drawing** (B = binary data → C = algorithm; A = red key → C; C → D = certificate icon):
✅ **A – Private Key**, **B – Large number of fixed size**, **C – Signature/Encryption Algorithm (RSA or ECC)**, **D – Signature**
(Signature generation takes a fixed-length number, in practice the SHA hash of the file, plus the **private** key.)

**Q5. Label the signature *validation* drawing** (A = certificate icon, B = green key → C → D = number):
✅ **A – Large number from output of signature generation step** (the signature), **B – Public Key**, **C – Signature/Encryption Algorithm (RSA or ECC)**, **D – Large number matching the number used as input during the signature generation step**

**Q6. Relationships diagram** (red key A → certificate C; B = number; green key D; arrows show B + A → C and C + D → B):
✅ **A – Private Key**, **B – Input number to signature generation step, output of signature validation step**, **C – Signature**, **D – Public Key**

**Q7. A hacker who obtains the inputs or outputs of signature validation can recreate the private key.** ✅ **False**. The public key, signature, and input number reveal nothing about the private key.

**Q8. A hacker who obtains the private key can generate a signature that passes validation with the public key.** ✅ **True**. That's why the private key never leaves the development environment.

**Q9. The asymmetric algorithm needs a fixed input size. How do you sign a firmware image of a different size?** ✅ **Use a hash function like SHA on the image to generate a fixed-size output.**

**Q10. Why must the hash produce very different output for slight input changes?** ✅ **It ensures any small unauthorized change in the firmware payload makes signature validation fail.**

**Q11. With properly generated keys, even a supercomputer would take more than a year to guess the private key.** ✅ **True**. It would take *multiple universe lifetimes*.

**Q12. Today's asymmetric encryption schemes are resistant to quantum computing, though that may not always be the case.** ✅ **False**. RSA and ECC are **not** quantum-resistant; NIST is developing post-quantum standards.

**Q13. A reason to use A/B instead of single copy or application updates?** ✅ **Ability to roll back to a previous known-good, unmodified root filesystem, even after an upgrade failure.** (It isn't the simplest, and it uses the *most* storage.)

## 10. C++ Templates and STL

**Q1. Value of k** (`#define min(a,b) ((a) < (b) ? (a) : (b))`, `i=6`, `j=20`, `k = min(++i, ++j)`) ✅ **8**
It expands to `((++i) < (++j) ? (++i) : (++j))`: i becomes 7, j becomes 21, 7 < 21 is true, so `++i` runs again → **8**. The macro evaluates its argument twice.

**Q2. Value of k** (`template <typename T> T min(T a, T b)`, `int i = 10; double j = 20.3; int k = min(i, j);`) ✅ **This code will result in a compiler error**
Template argument deduction fails because T can't be both `int` and `double`. (`min<int>(i, j)` would compile.)
